# Evaluation

The evaluation harness is built before the resolver, so that every change is measured against
fixed data. This page defines the datasets, metrics, baselines and protocol.

## Datasets

| Dataset | Built from | Size (target) | Labels | Committed? |
| --- | --- | --- | --- | --- |
| `cms-synthetic` | CMS inclusion terms and Index paths turned into phrases, with perturbations | 5,000+ | Exact by construction | Yes (public domain) |
| `mimic-silver` | "Discharge Diagnosis" sections of MIMIC-IV-Note, aligned to the admission's ICD-10 codes | 10,000+ phrases | Automatic, precision estimated by manual review | No |
| `mimic-gold` | Stratified sample of `mimic-silver` | 300–500 phrases | Hand-annotated, ideally reviewed by a certified coder | No |

### File format

Every dataset is a JSONL file, one example per line, read and checked by
`text2icd.eval.datasets`:

```json
{"id": "cms-synthetic:000042", "phrase": "aspiration pneumonia due to food",
 "gold": [{"code": "J69.0", "role": "primary"}], "release": "fy2027",
 "source": "cms-synthetic", "split": "dev", "meta": {"generator": "index-path"}}
```

| Field | Content |
| --- | --- |
| `id` | Unique within the dataset |
| `phrase` | The diagnosis phrase, on one line |
| `gold` | The full code set: one `primary` code first, then any `companion` codes. Each code has a `status` against `release` (`valid` by default, `mapped` with `mapped_to`, or `unmappable`; see [Code-set versions](#code-set-versions)) |
| `release` | The release the gold codes are checked against; one per dataset |
| `source` | Where the example came from, such as `cms-synthetic` or `mimic-silver` |
| `split` | `dev` or `test` |
| `meta` | Anything else: how the example was made, local identifiers for MIMIC-IV sets |

`text2icd eval validate FILE...` checks the format, repeated ids and mixed releases, checks each gold
code's status against the billable codes of the release (when it is fetched), and prints the dataset
hash. The hash is a SHA-256 over the examples in id order, so it identifies the content whatever the
line order or formatting; every result file records it.

### `cms-synthetic`

Generated by `text2icd eval synth -r <release>` from the release's graph
(`text2icd.eval.synthetic`); see [benchmarks/cms-synthetic](../benchmarks/cms-synthetic/README.md).

- Sources: Alphabetic Index paths read as phrases ("Pneumonia > aspiration > due to > food" becomes
  "aspiration pneumonia due to food"), with the code the term gives and its manifestation code as a
  companion; Tabular inclusion terms of billable codes; one column per Neoplasm Table and Table of
  Drugs row. A code that needs a 7th character gets one at random, with its meaning added to the
  phrase.
- Perturbations, one per phrase at random among those that apply: a nonessential modifier added,
  another word order, a common abbreviation ("CHF", "T2DM", "w/"), or one typo.
- FY2027 gives 142,757 examples (dev 67,812, test 74,945, split by category). A stratified sample
  of 1,067 is committed for CI regression tests.
- Purpose: CI regression tests and a public benchmark anyone can reproduce. It is not used to report
  real-world accuracy, because its phrases follow the classification's own wording.

### `mimic-silver`

1. Extract the "Discharge Diagnosis" section from each discharge summary and split it into items
   (`text2icd.eval.mimic.sections`). The section runs from its label to the next template label
   (usually `Discharge Condition:`). Group labels inside it (`Primary:`, `SECONDARY DIAGNOSES`
   underlined with `=====`, `Active issues:`, `PMH:`) are removed and kept as the item's group;
   bullets, numbers and leading labels such as `Dx:` are stripped; semicolons separate items on
   one line. A section with more than 40 items is not a diagnosis list and is left out.
   `text2icd eval mimic sections` prints aggregate counts: in MIMIC-IV-Note v2.2, 318,707 of
   331,793 discharge summaries (96.1%) have the section, giving 1,095,397 items (3.4 per note);
   51% of the items are under a primary or secondary group label.
2. Join the admission's ICD-10 codes from `diagnoses_icd` (`icd_version = 10`; codes are stored
   without the dot), in `seq_num` order (`text2icd.eval.mimic.gold`). Each code gets its status
   against the evaluated release (see [Code-set versions](#code-set-versions)).
3. Align each item to one of that admission's codes with an aligner that does **not** use the
   text2icd resolver (`text2icd.eval.mimic.align`): cosine similarity between the item and the
   code's description, embedded with SapBERT (an encoder trained to match biomedical synonyms,
   run locally through ONNX), one-to-one within the admission, best pair first. A pair is kept
   when its similarity is at least 0.70 and at least 0.05 above the item's next best code. Using
   the resolver would bias the labels toward its own mistakes, and no evaluated system uses
   SapBERT, so the labels do not favour one of them either.
4. Review 200 random alignments by hand and report the estimated label precision with the results
   (`text2icd.eval.mimic.audit`). `text2icd eval mimic audit sample` draws them from the `dev`
   split into a local review file; `audit review` asks for a verdict on each in the terminal
   (`y` right, `n` wrong, `?` cannot tell) and saves after each one; `audit score` reports the
   precision with a 95% Wilson interval, overall and by alignment score, to choose the thresholds.
   The review file holds MIMIC-IV phrases and stays under `data/`.

`text2icd eval mimic silver` builds the set into `data/processed/eval/mimic-silver.jsonl` and prints
aggregate counts. From MIMIC-IV v3.x and MIMIC-IV-Note v2.2 against FY2027: 122,288 discharge
summaries belong to admissions with ICD-10 codes; their 421,369 items give 175,035 aligned
examples (41.5%; dev 88,590, test 86,445), 9,387 of them scored by mapped match. The items that do
not align mostly name conditions that were not billed, or match two codes too closely.

### `mimic-gold`

Stratified by ICD-10-CM chapter and by code frequency (head, torso, tail), so rare codes are
represented. Each phrase gets its full code set, including companion codes, coded by hand against
the evaluated release (`text2icd.eval.mimic.annotate`):

- `text2icd eval mimic gold sample` draws the phrases from `mimic-silver`: a third from each
  frequency band of the silver codes (the codes making up the first half of the silver examples,
  the next 40%, the last 10%), spread over chapters, one item per note. Each comes with its
  admission's billed codes as candidates (replaced codes shown as their current replacements).
- `text2icd eval mimic gold annotate` is the coding session in the terminal: candidate numbers or
  codes, primary first, checked against the release's billable codes as they are typed, with
  Index lookups and code views from the graph; answers are saved after each phrase. Commas
  separate the codes of different diagnoses, and their number (`meta.diagnoses`) measures the
  condition splitter.
- `text2icd eval mimic gold build` writes `mimic-gold.jsonl` and reports how many phrases were
  coded, skipped and unsure, and how often the hand-coded primary code equals the silver one.

The rules for coders are in the [annotation guide](annotation-guide.md).

### Splits

`dev` and `test` are split by `subject_id`, so no patient appears in both: a salted hash of the
patient id puts half of the patients in each, so a patient's split never changes when a set is
rebuilt (`text2icd.eval.mimic.splits`). `test` is used only for reported numbers, never for tuning.
The calibration model for confidence is fitted on `dev`.

Once a set is final, `text2icd eval mimic freeze -d <name>` records the hash of its test split in
`data/processed/eval/frozen.json`. A rebuild that would change a frozen test split is refused, and
so is a test run on a set whose test split no longer matches.

### Code-set versions

MIMIC-IV codes were assigned under the release in force at each admission, roughly FY2016 to FY2022.
Some of those codes were later deleted or split (for example N18.3 became N18.30, N18.31 and N18.32 in
FY2021). `text2icd.eval.versions` checks each gold code against the evaluated release, using the
order files of every fetched release from FY2016 and the CMS conversion tables:

- `valid`: billable in the release, scored by exact match;
- `mapped`: billable in an earlier release and replaced since, scored by **mapped match** (a
  prediction counts if it is one of the codes in `mapped_to`) and reported separately. The
  replacements come from the conversion tables, read backwards (old code to the new codes that list
  it as their previous assignment) and followed across releases until codes billable in the target
  remain. Only references that name codes exactly (`N18.3`, `H35.20-H35.23`) are read backwards;
  broad ones (`I63.-`, "Codes in Categories T15-T19") name codes that still exist. A code that
  became a header with no conversion row maps to its billable subdivisions;
- `unmappable`: never billable, or deleted with no replacement; left out of the scores and counted.

`text2icd eval reconcile N18.3 -r fy2027` shows one code; `--dataset IN -o OUT` rewrites the
statuses of a whole dataset against the release.

Against FY2027, the 3,455,747 ICD-10 code assignments in the local MIMIC-IV `diagnoses_icd` (19,440
distinct codes) are 96.2% valid, 3.7% mapped (406 codes through the conversion tables, 4 through
their subdivisions) and 83 assignments (38 distinct codes) unmappable.

## Metrics

| Metric | Definition |
| --- | --- |
| Accuracy@1 | Primary predicted code equals the gold primary code |
| Accuracy@5 | Gold primary code is among the primary code and the first four alternatives |
| Category accuracy | First three characters match |
| Code-set F1 | Precision and recall of the full predicted code set against the gold set, including companions |
| Invalid-code rate | Share of predicted codes not billable in the release. Must be 0 |
| Selective accuracy | Accuracy at each coverage level when phrases below a confidence threshold are abstained |
| Calibration | Expected calibration error of the reported confidence |
| LLM call rate | Share of phrases that reached L3, and mean calls per phrase |
| Cost | US dollars per 1,000 phrases: each response's `usage` (input, output, cache read and cache write tokens) times the price table in `src/text2icd/resources/prices.toml` (`text2icd.llm.cost`) |
| Latency | p50 and p95 per phrase, with and without the LLM |

All metrics except latency are reported with 95% bootstrap confidence intervals (1,000 resamples
of the examples, fixed seed), overall, for the `valid` and `mapped` examples separately, and per
chapter. They are computed by `text2icd.eval.metrics.score`:

- A system returns, per example, a code set (primary code first), ranked alternates, an optional
  confidence, and its LLM calls, cost and latency (`text2icd.eval.predictions.Prediction`). An
  example with no prediction counts as wrong.
- Accuracy@5 reads the primary code then the alternates. Code-set precision, recall and F1 are
  pooled over all examples (micro), each predicted code matching at most one gold code.
- Examples with an `unmappable` gold code are counted and left out of the accuracy and code-set
  metrics; the invalid-code rate counts every predicted code, alternates included.
- Selective accuracy is accuracy@1 on the most confident 100%, 90%, ..., 50% of the examples; once
  a system reports any confidence, an example without one counts as 0. Calibration uses ten
  equal-width bins.

## Baselines

| Id | Method | Purpose |
| --- | --- | --- |
| B1 | BM25 over Tabular descriptions and inclusion terms (`-s bm25`) | Lexical floor |
| B2 | Embedding nearest neighbour over the same text (`-s embedding`, a local static model) | Semantic floor at zero API cost |
| B3 | A small, low-cost LLM given the top 20 codes from B2 | The "cheap LLM plus retrieval" approach text2icd must beat |
| B4 | A large, high-end LLM given the top 20 codes from B2, on a small sample with a hard budget | Reference ceiling for an expensive model |

Success criterion for v1.0: text2icd beats B3 on accuracy@1 and code-set F1 on `mimic-gold`, at less
than one tenth of B3's cost per 1,000 phrases.

B1 and B2 rank the billable codes whose description or inclusion term is closest to the phrase.
Codes made by adding a 7th character have no text of their own, so neither baseline can return
them; that is part of what they measure.

B3 and B4 (`-s llm`, `text2icd.eval.llm_baseline`) give the phrase and the top 20 codes of B2, with
their descriptions, to an LLM, which answers with candidate numbers through a JSON schema (one
primary code, optional companions, a confidence): it chooses, it never writes a code. One call per
phrase, with thinking off where the model allows it and low effort otherwise; each call's usage is
priced from `prices.toml`, and the run stops calling once its budget is spent (`-O budget=` or
`TEXT2ICD_LLM_BUDGET_USD`). The provider and model come from `TEXT2ICD_LLM_PROVIDER` and
`TEXT2ICD_LLM_MODEL` or `-O provider=... -O model=...`; the only provider implemented so far is
`anthropic`. B4 runs the same system with a large model on a sample:

```bash
uv run text2icd eval run -d cms-synthetic -s llm -O model=<small model> --limit 1000 -O budget=1
uv run text2icd eval run -d cms-synthetic -s llm -O model=<large model> --limit 200 -O budget=5
```

On MIMIC-IV sets, an LLM system runs only through an approved endpoint
([data and compliance](data-and-compliance.md#llm-endpoints-and-mimic-iv)).

B2 runs locally with a static embedding model (`text2icd.embeddings`, installed with
`uv sync --extra embeddings`); the default, `NeuML/pubmedbert-base-embeddings-8M`, was trained on
biomedical text. `-O model=<id>` selects another model2vec model. The MIMIC-IV aligner uses a
different model, so that silver labels do not favour B2.

| B2 embedding | 40.6% (40.2-41.0) | 55.2% (54.8-55.6) | 53.8% (53.4-54.2) | 41.6% (41.3-42.0) | 0% | $0 |

## Main-term recall

`text2icd eval main-terms -d <dataset>` measures the first step of the coder's workflow: whether
Index search puts a right main term (one whose subterms lead to the gold code or a code above it)
among the first 1, 5 or 10 found, searching main terms only or all terms
(`text2icd.eval.main_terms`). It chose the graph's tokenizer
([architecture](architecture.md#knowledge-graph)) and will measure main-term selection in Phase 5.

## Text understanding

`text2icd eval parse -d <dataset>` reads every phrase of a split with `text2icd.text.parse` and
reports aggregate counts (`text2icd.eval.parsing`): diagnoses per phrase, phrases with an
abbreviation expanded, flags, relations and modifiers. Where the number of diagnoses is known
(`meta.diagnoses` in `mimic-gold`, and one for every `cms-synthetic` phrase), it reports the share
of phrases split into that many, with a Wilson interval. `--show N` lists mismatched phrases, for
public datasets only.

The accuracy of abbreviation expansion is measured by hand on MIMIC-IV dev discharge diagnoses
(`text2icd eval mimic abbrev sample | review | score`): one expansion drawn at random from each
note that has one, a seeded sample of 200, judged right or wrong in the terminal, and the accuracy
with a Wilson interval, overall and by how the meaning was chosen (the only one, a hint, or the
default of an ambiguous abbreviation).

Phase 4 targets: at least 95% of `mimic-gold` dev phrases split into the annotated number of
diagnoses, and at least 95% of expansions right. Results so far, FY2027:

| Measure | Result |
| --- | --- |
| `cms-synthetic` dev, one diagnosis per phrase | 95.7% of 67,812 |
| `mimic-silver` dev, phrases with an abbreviation expanded | 8.9% of 88,590 |
| `mimic-gold` dev, number of diagnoses | waits for the annotation |
| Abbreviation expansion accuracy | waits for the review |

## Protocol

- `text2icd eval run -d <dataset> -s <system>` runs a system on one split (`dev` by default; `test`
  must be asked for) and writes a result file under `data/processed/eval/results/` (git-ignored).
  Its first line records the git commit (and whether the tree had changes), the release and graph
  hash, the dataset hash, split and selection, the system's settings and model ids, the times and
  the Python version; then one prediction per example, by id, with no phrase text. The metrics are
  written next to it (`.metrics.json`). `--limit N` runs on a seeded random sample, for costly
  systems; `-O key=value` passes system options.
- Datasets are named by path or by name: `cms-synthetic-sample` (the committed sample),
  `cms-synthetic` (the full local set of the release), `mimic-silver`, `mimic-gold`.
- `text2icd eval report RESULT...` renders a markdown table comparing runs, with intervals and a
  provenance line per run; `--by-chapter` adds per-chapter tables. Only aggregate numbers appear.
- The CI integration job runs B1 on the committed `cms-synthetic` sample, so the harness itself is
  exercised on every pull request.
- Ablations switch off one component at a time: no Index walk, no Tabular verification, no
  abbreviation lexicon, no L2, no L3.
- Error analysis groups failures into buckets (wrong main term, wrong subterm, wrong Tabular child,
  missing companion code, missing 7th character, label noise) and tracks bucket sizes across
  iterations. Only bucket counts are published, never examples from MIMIC-IV.
